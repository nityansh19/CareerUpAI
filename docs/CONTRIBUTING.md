# Contributing

Keep changes focused, reviewable and easy to understand.

## Workflow

1. Start from the latest `main` branch.
2. Make one logical change at a time.
3. Run relevant checks before committing.
4. Use clear commit messages that describe the change.
5. Update documentation when setup or behavior changes.

## Pull-request quality

A good change explains what changed, why it changed, how it was tested and any known limitations.

## Scope discipline

Avoid mixing unrelated refactors, UI redesigns and feature work in the same change. Smaller changes are easier to review, debug and revert.

## Before requesting review

Check for temporary logs, dead code, exposed secrets, broken links, missing loading/error states and unintended mobile regressions.
