# Contributing to CareerUpAI

Thanks for helping improve CareerUpAI. Keep changes focused, easy to review, and aligned with the product's Discover, Prepare, Act, and Track areas.

## Local workflow

1. Install dependencies for the area you are changing.
2. Create a focused branch for the change.
3. Run the relevant development server and verify the affected flow.
4. Build the frontend before opening a pull request.
5. Keep secrets and local environment files out of Git.

## Change guidelines

- Prefer small, purposeful components over oversized page files.
- Reuse existing UI patterns before introducing new ones.
- Keep public pages and authenticated workspace concerns separated.
- Document new environment variables and setup requirements.
- Avoid committing generated build output or credentials.

## Pull requests

A good pull request explains what changed, why it changed, how it was tested, and includes screenshots for visible UI changes.

Use clear commit messages such as `feat: add career roadmap filters`, `fix: preserve dashboard state`, or `docs: clarify backend setup`.
